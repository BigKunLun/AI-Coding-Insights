# 路线图（Roadmap）

> 最后更新：2026-08-15 ｜ 当前版本：`1.0.0-alpha.1`（v1 预发布）
> 这份路线图只写**已经拍板的事**。没想清楚的不写进来占位。

## 现在能用到什么程度（诚实版）

三家 harness 的成熟度**不一样**，别把它们当同一把尺：

| Harness | 验证深度 | 说明 |
|---|---|---|
| **Claude Code** | 🟢 最充分 | 本项目全部指标最初就是照它的 transcript 形状定义的，能力全集；作者本机长期真实使用，跨版本样本量最大。 |
| **Codex CLI** | 🟡 已有实测样本 | 能力集按**实测本机 rollout 记录**逐条声明，脱敏样本已进 `tests/fixtures/codex/`。拿不准的能力一律不声明（宁可标「未测量」）。子代理 / MCP 等概念在其记录里测不到，报告会明确标注。 |
| **opencode** | 🟠 单版本单样本，最薄的一环 | parser 依据本机 v1.18.18 实库（`session`/`message`/`part` 三张表）+ 反编译服务端 bundle 里的 schema 定义写成。**只验证过这一个版本**，SQLite schema 随版本漂移的风险最高。 |

档位（探索 / 进阶 / 精通 / 引领）挂 **beta 角标**：阈值是初设值，只经本机单人分布
（`calibrate --replay`）粗校，**没有人群分位背书**。作自我定位参考，不作横向评比、
更不作考核依据。

## 待办（已排期）

- **阈值人群校准**：现在只有单人分布。要把档位阈值从「初设值」变成「有分位背书」，
  需要一批真实用户愿意回传**脱敏标量**（不含任何路径与文本）。在拿到之前，beta 角标不摘。
- **opencode schema 漂移跟进**：目前是「不认识的 schema 就显式报错，不静默走样」。
  随版本跟进映射，并补齐第二个版本的 fixtures。
- **能力盲区的工具名跨来源对位**：盲区判定现在按 Claude Code 的工具名匹配
  （如 `TodoWrite` / `WebSearch`），Codex 的 `update_plan` / `web_search`、opencode 的同类工具
  匹配不上，会误报成「没用过任务清单 / Web 取证」。这是已知误报，修法是给每个能力配
  一张跨来源的工具名映射表。
- **三端人工冒烟留证**：每版每端跑一次全流程并留报告文件，作为发布闸门的一部分。
- **演示 GIF 的终端段**：报告那一屏已录（`docs/demo/demo.gif`，15 秒滚动通览，
  逐帧真实渲染，`录制GIF.py` 可一条命令重录）。**「装 → 触发」的终端录屏仍缺**——
  那要真跑一次带 LLM 编排的完整会话并录屏，机器造不出来。分镜见
  [`docs/demo/录制脚本.md`](demo/录制脚本.md)。

## v1 明确不做（非目标）

写在这里是为了让人知道「不是忘了」，而是想清楚后决定不做：

- **MCP server 化**——进 roadmap 备选，v1 不做。
- **英文物料 / HN 首发**——先在中文社区验证，英文等验证后再投。
- **人群分位阈值**——数据攒不出来就不假装有，诚实标注单人口径。
- **团队评估 / 奖惩功能**——人在环是定位级红线：机器只给分析与证据，判决在人。
  这条不会因为「有人想要」而松动。
- **Claude Code 之外的 SessionEnd 自动快照**——`auto-scan` 依赖生命周期 hook，
  Codex / opencode 无对位机制，故为 CC 专属能力，其余两家显式声明降级。

## 发布闸门（v1 单闸门：三家齐了才发）

1. `uvx ai-coding-insights install` 在三家各自落位成功（`--print` 预演 + 真实安装冒烟各一份）。
2. 三端各自触发 → 解析各自会话 → 出完整报告，人工冒烟通过并留证。
3. `uv run pytest` 全绿；三家脱敏 fixtures 进 CI；三个安装适配器各有契约测试。
4. 隐私铁律扩展到新源：三家的自由文本全部过 `redact` 网。
5. 报告正确渲染：档位 beta 角标、降级 caveat、来源口径标注。
6. 推广物料齐备：中文 README、demo 报告、GIF（报告段已齐，终端段待录）、roadmap。
7. 主指标时钟自发布日起算 3 个月。
